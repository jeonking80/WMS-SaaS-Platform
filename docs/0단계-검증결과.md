# 0단계 개발 기반 검증 결과

검증일: 2026-10-19. 대상은 현재 클라우드 작업 환경의 P0 구현이다. GitHub Actions 실행, 새 클라우드 환경 복원, 외부 데모 배포 결과를 뜻하지 않는다.

## 구현한 범위

- Next.js·React·TypeScript·Tailwind 앱 골격과 초기 개발 상태 화면
- Node/npm 버전 기준, 정확한 의존성 버전과 잠금 파일
- 로컬 환경변수 생성, 개발·테스트 PostgreSQL 컨테이너, 최초 `tenants` 마이그레이션과 합성 회사 시드
- `/api/health`와 실제 DB·최초 테이블을 확인하는 `/api/ready`
- 단위·PostgreSQL 통합·Chromium E2E 및 GitHub Actions 설정
- 기술 결정·DB 설계·API 명세와 README 실행 절차

서브에이전트는 DB 기반, 테스트·CI 기반, 인증 라이브러리 검증을 나눠 수행했다. 주 에이전트가 앱·상태 API·환경 설정을 구현하고 통합 실행을 검증했다. DB·실행 안전성에 대한 추가 읽기 전용 검토도 수행했다.

## 실행 결과

| 검사 | 결과 | 확인한 내용 |

| `npm run db:migrate` 최초·반복 실행 | 통과 | 최초 1개 적용, 다음 0개 적용 |
| `npm run db:seed` 반복 실행 | 통과 | 고정 합성 회사 A/B의 중복 생성 방지 |

| `npm run test:unit` | 10개 통과 | 연결 설정 검증, 준비 상태 응답·오류 비공개 처리 |

| 개발 DB 중단·복구 | 통과 | DB 중단 중 health 200·readiness 503, 복구 후 readiness 200 |
| Git 제외와 변경 검사 | 통과 | `.env.local`, 의존성, 빌드·테스트 결과 제외, 기존 기획서 보존 |

최종 자동 테스트는 **단위 10개 + 통합 2개 + E2E 3개 = 15개 통과**다. 건너뛴 테스트는 없다. 아래 미구현 업무 시나리오는 아직 테스트 대상에 포함되지 않았다.

마이그레이션 통합 검사는 빈 테스트 스키마 적용·회사 기본값·재실행 데이터 보존·공백 및 NULL 이름 거절을 확인한다. 인증 호환성 검사는 임의 테스트 스키마에서 Better Auth 마이그레이션, 내부 계정 생성, HTTP 로그인·쿠키 세션, 공개가입 400, 미인증 사용자 생성 401, 로그아웃 무효화, 인증 테이블 격리 및 스키마 정리를 확인한다. 이 결과는 앱에 로그인 기능이나 회사 격리가 구현되었다는 의미가 아니다.

## 검증 중 문제와 조치

- 기본 npm 캐시 위치에 쓰기 문제가 있어 `/workspace/.npm-cache`를 사용했다. TLS·패키지 무결성 검증은 유지했다.
- `cdn.playwright.dev`에서 Playwright 전용 Chromium 다운로드가 네트워크 정책으로 403 응답을 반환했다. 현재 환경에 설치된 Chromium 154.0.8037.57을 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`으로 지정하여 E2E를 통과했다. CI에서는 Playwright 지정 브라우저 설치 경로를 유지했으며, 그 원격 실행 결과는 미확인이다.
- 최초 E2E 실행과 `npm ci`를 겹쳐 실행하여 모듈 로딩 오류가 발생했다. 재설치 완료 후 타입·단위·통합·E2E를 순서대로 재실행해 통과했다. 이후 설치와 서버·테스트는 순차 실행한다.
- 인증의 최초 단순 초기화 탐색은 연결 설정·인증 스키마가 없어 실패했다. 이후 실제 테스트 DB의 독립 스키마에 공식 마이그레이션을 적용하고 반복 가능한 통합 테스트로 검증했다.

## 현재 제한과 다음 단계

P0의 로컬 실행 기반과 기술 호환성 검증을 완료했다. 개발 서버와 개발·테스트 DB가 실행 중이며, 프로세스는 새 환경에서 다시 시작해야 한다. 재설치 `install_script`와 시작 `start_skill`은 클라우드 환경 설정 초안으로 저장했다. 저장 자체는 게시나 새 작업에서의 복원 검증을 뜻하지 않는다.

다음은 개발계획서 P1의 앱 인증·회사·역할·DB 계정 분리·RLS다. 현재 공개 로그인, 앱 사용자 계정, 회사별 접근 제어, 기준정보 UI, 전표·재고 처리, 운영 데모는 제공하지 않는다. PostgreSQL 관리자 계정은 독립 로컬 초기화용이므로 업무 API 구현 전 일반 앱 권한으로 교체해야 한다.

GitHub Actions와 외부 배포는 아직 실행하지 않았다. 실행 및 재현 명령은 [README](../README.md)를 따른다.
