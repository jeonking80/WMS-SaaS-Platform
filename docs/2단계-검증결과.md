# WMS Lite 2단계 검증 결과

검증일: 2026-10-20 (Asia/Seoul). 기존 로컬 PostgreSQL 17.9, Node.js 24, Next.js 16, 시스템 Chromium 환경에서 검증한다. GitHub Actions는 제거했으며 사용하지 않는다. 모든 서브에이전트는 gpt-6.1-sol을 사용했다.

## 구현 범위

- P2-01: 품목·창고·로케이션 관리 화면/API. 관리자 변경, 작업자 조회, 회사·창고 범위 코드 고유성, 비활성화 규칙.
- P2-02: 전표·명세 스키마와 목록·상세. 회사 포함 복합 FK, 위치·창고 일치, 모든 업무 테이블 FORCE RLS.
- P2-03: 입고·출고·이동 초안 생성·수정·취소. 품목 1~20개, 중복 거절, 양의 정수 수량, 유형별 위치 검증.
- P2-04: 전표 버전·행 잠금, 동시 변경 한 건만 성공, 취소 후 변경 금지, 조회자 초안 접근 차단, 충돌 안내와 다시 불러오기.

## 실행 및 결과

`npm run db:setup`으로 신규 마이그레이션 1개를 적용했다. `npm run db:check`에서 앱 계정의 비소유자·비관리자·RLS 우회 불가 조건을 확인했다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium NEXT_TELEMETRY_DISABLED=1 npm run verify
```

타입 검사, 단위 51개, PostgreSQL 통합 11개, 프로덕션 빌드와 브라우저/API E2E 15개가 통과했다. 이후 강화한 P2 API 테스트도 통과했으며, 추가한 브라우저 테스트는 아래 명령으로 별도 실행하여 1개가 통과했다. 최종 검증된 고유 테스트는 단위 51개·DB 통합 11개·E2E 16개, 총 78개다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e -- tests/e2e/p2.spec.ts --grep "P2 browser"
```

브라우저 검사 최초 실행에서는 select/textarea의 라벨 텍스트 기반 선택자가 옵션·입력 내용을 포함하여 요소를 찾지 못했다. 실제 접근성 역할과 이름을 사용하는 선택자로 수정했으며 최종 실행은 통과했다. 검사 생략이나 인증 제한 완화는 하지 않았다.

## 주요 검증 근거

실제 제한된 DB 역할로 신규 네 테이블의 RLS·컨텍스트 없는 접근·회사 A/B 분리와 회사 포함 FK를 검사한다. API 테스트는 역할 제한, 다른 회사 참조, 같은 회사 코드 중복, 비활성 참조, 0/음수/소수/상한 초과 수량, 중복·21개 명세, 동시 버전 변경, 초안 취소를 검증한다. 자체 업무 API의 JSON·출처 검사와 오류 상세 비노출도 단위 테스트한다.

브라우저 테스트는 기준정보 등록, 전표 작성·수정·취소와 취소 후 읽기 전용 상태, 오래된 버전 충돌 후 다시 불러오기, 조회자 업무 화면 차단을 검사한다. 테스트가 만든 UUID 데이터만 전용 로컬 DB에서 정리하며 기존 데이터를 삭제하지 않는다.

## 범위와 다음 단계

현재고·원장 테이블과 확정 API는 아직 없으므로 초안 작업은 재고를 변경하지 않는다. 잔량이 있는 위치의 비활성화 방지는 현재고를 추가하는 3단계에서 구현한다. 현재는 초안 참조와 활성 하위 위치를 기준으로 비활성화를 제한한다. 기준정보 목록 최대 1,000개, 전표 목록 최대 100개이며 검색·페이지네이션은 미구현이다.

다음 단계는 현재고·원장, 입고 확정, 멱등성 및 재고 트랜잭션 검증이다. 외부 배포와 새 환경 복원 검증은 이번 단계에서 수행하지 않았다.
