# WMS Lite 3단계 검증 결과

검증일: 2026-10-20 (Asia/Seoul). Node.js 24, Next.js 16, PostgreSQL 17.9, 시스템 Chromium 환경에서 실행했다. 서브에이전트는 모두 gpt-6.1-sol을 사용했다. GitHub Actions는 사용하지 않았다.

## 완료 범위

- P3-01: 현재고·원장·멱등 요청·감사 기록 스키마와 회사 RLS. 잔량 고유·비음수·상한, 원장 중복 제약, 원장·감사·요청 기록의 앱 UPDATE/DELETE 금지.
- P3-02: INBOUND 초안 확정. 전표·기준정보·잔량 잠금, 없는 잔량 생성, 원장·현재고·상태·감사 기록 일괄 커밋.
- P3-03: 같은 키·요청 재반환, 키 내용 충돌, 다른 키로 같은 전표 재확정 차단. 통신 실패 재시도와 잠금 오류 구분.
- P3-04: 입고 확정 화면, 현재고·원장 조회, 전체 수량 대조, 양수 재고 기준정보 비활성화 차단.

## 로컬 실행 결과

`npm run db:setup`으로 신규 마이그레이션을 적용했다. `npm run db:check`에서 비소유자·비관리자·RLS 우회 불가 앱 계정을 확인했다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium NEXT_TELEMETRY_DISABLED=1 npm run verify
```

## 핵심 검증 근거

- 입고 100개는 잔량 100, 원장 +100, POSTED 전표, 감사 1건, 성공 요청 결과 1건을 만든다.
- 같은 키 동시 요청은 같은 응답을 반환하고 한 번만 반영된다. 다른 키로 재확정하거나 같은 키의 버전·전표를 바꾸면 충돌한다.
- 서로 다른 전표가 같은 최초 잔량을 동시에 생성해도 합계가 일치한다.
- 독립 DB 연결에서 전표 잠금을 먼저 잡고 수정·확정 요청이 모두 잠금 대기에 도달했음을 확인한 후 해제한다. 한 작업만 성공한다.
- 테스트 DB 트리거를 감사 기록 및 요청 결과 삽입 단계에 각각 설치해 오류를 주입한다. 원장·상태 변경이 진행된 뒤에도 현재고·원장·상태·감사·요청 결과가 모두 롤백되고 같은 키 재시도가 성공한다. 앱에 오류 주입 API를 만들지 않았다.
- 브라우저에서 서버가 입고 확정을 커밋한 응답을 받은 뒤 네트워크 응답을 차단한다. 화면의 재시도는 최초 키를 유지하고 입고는 한 번만 반영된다. DB COMMIT 자체의 네트워크 단절은 별도로 주입하지 않았다.
- 재고 대조는 실제 100/100 일치를 확인하고, 테스트 소유자 계정으로 잔량만 123으로 바꾸면 123/100 불일치를 정확히 보고한다. 자동 보정하지 않으며 테스트에서 원복한다.
- 조회자는 재고·원장·대조를 읽지만 입고 확정은 403이다. 다른 회사의 전표 확정은 404이며 재고·원장도 노출되지 않는다. 재반환에도 현재 역할을 검사한다.
- 잔량이 남은 품목·위치·창고의 비활성화와 확정 전표의 수정·초안 취소를 차단한다.

## 제한과 다음 단계

출고·이동 확정과 확정 취소는 아직 구현하지 않았다. 현재고·원장 목록은 최대 1,000개이며 검색·페이지네이션은 후속 범위다. 대조는 회사 전체를 검사한다. 감사 기록 조회 화면은 6단계 범위다. 멱등 성공 기록은 자동 만료시키지 않는다. 외부 배포·성능 측정·새 환경 복원은 이번 단계에서 수행하지 않았다.

다음은 4단계 출고 확정·재고 부족 검사 및 재고 100에 80개 출고 두 건의 동시 경합 검증이다.
