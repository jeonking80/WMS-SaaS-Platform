# WMS Lite 5단계 검증 결과

검증일: 2026-10-20 (Asia/Seoul). Node.js 24, Next.js 16, PostgreSQL 17.9, 시스템 Chromium 환경을 사용했다. 모든 서브에이전트는 gpt-6.1-sol이며 GitHub Actions는 사용하지 않았다.

## 구현 범위

- P5-01: 같은 창고 내 이동 확정. 출발 차감·도착 증가를 한 트랜잭션으로 처리하고 모든 위치·품목 잔량을 일정 순서로 잠근다.
- P5-02: 관리자 전체 확정 취소. 원본 연결 반대 전표·반대 원장·REVERSED 상태·감사·멱등 응답을 함께 커밋한다. 원본 원장·명세·확정 시각은 유지한다.
- P5-03: 입고·이동 취소 잔량 부족 거절, 출고 취소 복구, 중복·동시 취소 방지, 같은 요청 재시도, 원본/반대 전표 조회 화면.

`npm run db:setup`으로 마이그레이션 0005를 적용하고 `npm run db:check`에서 앱 계정의 비소유자·비관리자·RLS 우회 불가 조건을 확인했다.

## 검증 명령

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium NEXT_TELEMETRY_DISABLED=1 npm run verify
```

## 실행 결과

| 검증 | 최종 결과 |
|---|---|
| 타입 검사 | 통과 |
| 단위 테스트 | 83개 통과 |
| PostgreSQL 통합 테스트 | 40개 통과 |
| 프로덕션 빌드 | 통과 |
| 브라우저/API E2E | 25개 통과 |

최초 실행에서는 기존 초안 취소 단위 테스트가 새 반대 전표 조회에 대한 모의 응답을 제공하지 않아 실패했다. 모의 응답을 추가하고 취소된 초안의 reversal_document_id가 null임을 검사한 뒤 전체 검증 명령을 다시 실행해 모두 통과했다. 테스트 생략이나 검증 조건 완화는 하지 않았다.

전체 검증 후 부분 명세 등 version 외 필드를 400으로 거절하는 입력 검사를 보완했다. 프로덕션 빌드를 다시 통과하고 아래 API E2E 1개를 재실행하여 부분 입력 거절·상태 미변경 및 정상 전체 취소까지 확인했다.

```sh
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e -- tests/e2e/p5.spec.ts --grep 'P5 transfer and linked'
```

## 주요 검증 근거

- 재고 100에서 위치 간 60 이동 후 40/60, 취소 후 100/0을 확인한다. 원장 합계와 현재고가 일치하며 창고 전체 수량은 보존된다.
- 같은 위치 및 다른 창고 위치로 이동하는 요청은 재고 효과 전에 거절한다.
- 입고 취소는 원래 도착 위치 차감, 출고 취소는 원래 출발 위치 복구, 이동 취소는 양쪽 역방향 효과를 기록한다. 비활성 과거 품목도 출고 취소로 복구할 수 있다.
- 원본 원장과 posted_at을 유지하고 반대 전표의 원본 FK·명세·반대 원장을 확인한다. 다른 회사 연결·중복 반대 전표·자기 참조는 DB 제약으로 거절한다.
- 입고·이동 취소에 필요한 잔량이 부족하면 전표·명세·원장·잔량·감사·요청 결과가 모두 미변경이다.
- 원본 행을 제어 연결로 잠근 뒤 독립 연결의 동시 취소를 겹쳐 실행한다. 같은 키는 같은 성공 결과로 재반환하고 다른 키는 한 건만 성공한다. 반대 전표는 한 건이다.
- 반대 방향 이동 두 건도 실제 잔량 잠금 대기에 도달시킨 뒤 해제해 같은 잠금 순서와 총수량 보존을 확인한다.
- 마지막 멱등 응답 삽입에 테스트 DB 트리거 오류를 주입한다. 그 전에 생성한 반대 전표·명세·원장·잔량·원본 상태·감사까지 전부 롤백하고 같은 키 재시도가 성공한다. 앱에 오류 주입 경로를 만들지 않았다.
- 브라우저에서 이동 확정·관리자 취소·원본/반대 전표 열기·작업자 취소 버튼 미노출을 검사한다. 서버가 커밋한 취소 응답을 차단해도 같은 키로 재시도하여 한 번만 반영한다.
- 작업자·조회자의 취소는 403이며 재반환에도 적용한다. 다른 회사 전표는 404다. 반대 전표의 재취소·재확정·초안 취소와 REVERSED 원본의 새 확정 요청은 거절한다.

## 범위와 다음 단계

부분 취소와 취소의 재취소는 지원하지 않는다. 기존 확정 키의 재반환은 과거 성공 응답이며 현재 상태는 상세 조회로 확인한다. 비활성 기준정보를 참조한 취소도 활성 상태를 자동 변경하지 않는다.

검색·페이지네이션·대시보드·조회자의 확정 이력 접근 확대·사용성 및 성능 측정은 6단계에서 진행한다. 외부 배포와 새 환경 복원은 이번 단계에서 실행하지 않았다.
