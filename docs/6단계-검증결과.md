# WMS Lite 6단계 검증 결과

검증일: 2026-10-20. gpt-6.1-sol 서브에이전트로 조회 API, 대시보드, UI, 회귀 테스트와 성능 측정을 분담했다. GitHub Actions는 사용하지 않았다.

## 구현 범위

- P6-01: 재고·원장·전표 검색 및 서버 페이지 처리, 창고·위치·품목 필터, 전표 유형·상태·서울 날짜 범위. 조회자는 확정 이력 전용 화면/API만 접근하며 초안은 계속 차단한다. 관리자는 담당자·작업·전표별 감사 로그를 조회한다.
- P6-02: 재고 보유 품목, 오늘 입출고·취소, 미확정 출고, 최소재고 미달, 최근 7일과 최근 확정 전표. 관리자 품목 설정에 최소재고를 추가했다.
- P6-03: 확정·확정 취소 전 명세 확인창, 처리 중 버튼 잠금과 기존 멱등 키 재시도, 로딩·조회 실패·빈 목록 구분, 태블릿 화면과 회사 전환 후 데이터 격리.
- P6-04: 전용 합성 회사에 원장·전표·잔량 각 1만 건을 생성하여 주요 API와 브라우저 표시 시간을 별도로 측정하는 재현 스크립트. 측정 결과는 [성능 측정](6단계-성능측정.md)에 기록한다.

마이그레이션 0006(누적 7개)을 개발 DB에 적용했다. `npm run db:check`에서 앱 계정의 비소유자·비관리자·RLS 우회 불가 조건을 확인했다.

## 검증 명령 및 결과

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium NEXT_TELEMETRY_DISABLED=1 npm run verify
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:performance
```

| 검증 | 결과 |
|---|---|
| 타입 검사 | 통과 |
| 단위 테스트 | 100개 통과 |
| 실제 PostgreSQL 통합 테스트 | 42개 통과 |
| 프로덕션 빌드 | 통과 |
| 브라우저/API E2E | 기존 25개 + 최종 P6 3개 통과 |
| 총 고유 테스트 | 170개 통과 |

최초 전체 검증에서는 기존 P0~P5 E2E 25개와 P6 API 검사가 통과했고, P6 태블릿 검사에서 긴 창고·위치 선택지가 화면을 넘는 문제를 발견했다. 입력 요소 너비와 긴 문자열 줄바꿈을 수정하고 다시 빌드했다. 새 원장 기간 UI 검사를 추가하면서 이전 빌드를 사용하는 실행은 중단했다. 재실행에서 태블릿 검사가 통과했으며, 재고 테스트의 선택자 대기는 선택지 텍스트까지 포함하는 정확한 label 비교 때문이어서 접근성 역할 기반 combobox 선택자로 수정했다. 검증 조건을 완화하지 않았다. 최종 빌드에서 `npm run test:e2e -- tests/e2e/p6.spec.ts`의 3개 시나리오가 모두 통과했다. 전체 명령의 최초 실행은 위 실패로 완료되지 않았으며, 표는 최초 통과한 기존 범위와 수정 후 해당 범위 재검증 결과를 합친 고유 테스트 수다.

## 검증 근거

- 단위 테스트: 페이지·페이지 크기·UUID·검색어·날짜·상태·유형의 유효성 및 SQL 검색 와일드카드 문자 처리.
- 실제 PostgreSQL 통합 테스트: 서울 자정 경계, 취소된 원본의 최초 확정 실적 보존, 취소일 별도 집계, 잔량 행 없는 활성 품목의 0 재고 부족 판정, 비활성 품목 제외, 회사별 집계 분리, 최소재고 DB 제약.
- API E2E: 실제 확정 전표 30건으로 페이지 총수·중복 없는 다음 페이지·필터를 확인한다. 조회자의 확정 이력 접근과 초안/다른 회사 차단, 감사 로그 관리자 제한, 최소재고 변경과 집계를 검사한다.
- 브라우저 E2E: 같은 브라우저에서 A 로그아웃 후 B 로그인하여 대시보드·이력·재고가 바뀌는지 검사한다. 768px 태블릿에서 가로 넘침과 읽기 전용 이력을 확인한다. 빈 결과와 503 오류를 구분하고 로딩 및 페이지 이동·검색을 검사한다.
- 기존 입고·출고·이동·확정 취소의 회귀 시나리오는 새 확인창을 거치도록 갱신했다. 원장 API 검사는 테스트 품목으로 범위를 지정해 페이지 기본값에 영향을 받지 않게 했다.

현재고에는 과거 잔량 조회 기능이 없다. 재고 화면의 기간·유형·상태 조건은 원장에만 적용된다고 표시하고 현재고 요청에서 해당 조건을 제외했다. 원장 전표 ID에서 읽기 전용 확정 이력으로 이동할 수 있다.

## 성능 검증 결과

원장·전표·잔량 각 10,000건의 실제 합성 데이터를 확인하고 6개 API와 5개 화면을 측정했다. 각 구간 준비 실행 1회 후 5회 측정, 동시 사용자 1명이다. 최종 최댓값은 API 38.30ms, 브라우저 표시 314.93ms로 이 조건에서 2초 목표를 충족했다. 전용 회사와 합성 계정 제거도 완료했다.

최초 대량 입력 직후 원장 API가 503을 반환했으나 통계 갱신(`ANALYZE`)을 준비 절차에 추가한 뒤 성공했다. 통계 갱신은 측정 시간에서 제외한다. 쿼리 실행 계획으로 원인을 확정한 것은 아니며, 통계가 갱신된 상태의 관측 결과다. 앱 제한 시간이나 검증 조건은 완화하지 않았다. 전체 표본과 환경은 [성능 측정](6단계-성능측정.md)에 기록한다.

## 범위와 다음 단계

이번 단계는 로컬 프로덕션 빌드와 합성 데이터 검증이다. 성능 결과는 단일 사용자·같은 호스트 조건이며 운영 네트워크 또는 다중 사용자 부하를 보장하지 않는다. 기준정보 필터 선택 목록은 회사별 창고·위치 최대 1,000개다. 다음 7단계는 배포·백업/복원·데모 점검이며 외부 배포와 새 환경 복원은 아직 실행하지 않았다.
