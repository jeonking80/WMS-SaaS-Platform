# WMS Lite 7단계 검증 현황

작성일: 2026-10-20 (Asia/Seoul). 모든 서브에이전트는 gpt-6.1-sol이며 GitHub Actions는 만들거나 실행하지 않았다.

**진행 상태: 배포 준비·복원·데모 구현 및 로컬 검증 완료. 외부 공개 배포는 미실행.** 사용자는 아직 배포 서비스 계정이 없어 배포 방식 추천을 요청했다. Railway의 독립 Docker 앱·PostgreSQL 서비스를 우선 제안했다. 실제 계정·프로젝트 연결 및 비용 선택이 필요하며 현재 공개 URL은 없다.

## 구현

- Docker 다단계 빌드와 Next.js standalone 런타임. 앱은 제한된 wms_app 연결만 사용하고 마이그레이션·관리 연결은 별도 operations 작업에 둔다.
- 독립 Compose DB 볼륨·내부 네트워크. DB 포트는 공개하지 않으며 웹은 외부 TLS 프록시 앞의 호스트 loopback에 연결한다.
- 합성 데모 전용 DB/회사·계정·재고 시드. 조회자·작업자·관리자 비밀번호를 분리하며 개발용 공용 비밀번호는 사용하지 않는다. 기존 데모 데이터를 덮어쓰거나 비밀번호를 재설정하지 않는다.
- 로컬 PostgreSQL custom 백업과 새 DB 복원 도구. 기존 대상 DB·원본 DB·기존 백업 파일 덮어쓰기를 거절한다.
- 조회 전용 데모 점검·시연 영상 녹화 스크립트와 운영 문서.

## 백업·복원 근거

`npm run test:restore`를 실제 PostgreSQL 17에서 실행했다. 빈 임시 DB에 7개 마이그레이션을 적용하고 다른 새 DB에 복원했다. [원본 결과](p7-restore-result.json)는 접속정보나 비밀번호를 포함하지 않는다.

- 2개 회사, 입고 100·출고 30·잔량 70의 원장 대조에서 불일치 0건.
- 사용자·계정·만료된 세션·소속·검증 기록·감사·멱등 응답까지 비어 있지 않은 데이터로 복원.
- 모든 앱 테이블의 행 수와 데이터 지문 일치, 소스 데이터 미변경.
- 복원된 비밀번호 해시 확인과 실제 wms_app 연결의 세션/소속 읽기 성공.
- 9개 업무 테이블의 ENABLE/FORCE RLS 보존, 타 회사 조회·쓰기 차단.
- 원장·감사·멱등 기록 UPDATE, 잔량 DELETE, public 스키마 CREATE 거절.
- 검증용 소스·복원 DB와 임시 백업 파일 정리 완료.

이 검증은 동일한 로컬 PostgreSQL 클러스터에서 기존 역할을 재사용했다. 외부 제공자 자동 백업이나 새 클러스터의 역할·암호 복구까지 검증한 것은 아니다.

## 실행 결과

- 단위 테스트 100개·PostgreSQL 통합 테스트 42개 통과.
- Node 24.19.0/Next.js 16.4.2 Docker runner 빌드 및 일반 사용자 실행 확인.
- 실제 runner의 `/api/health`, `/api/ready`, 정적 파일 200 및 세 역할의 데모 로그인·조회·권한 검증 통과.
- 빈 독립 데모 DB에 7개 마이그레이션 적용과 앱 역할 검사, 합성 시드 반복 실행 성공.
- opt-in 누락·DB 이름 불일치·공유 비밀번호·개발 비밀번호 재사용 거절 확인.
- 실제 시연 영상: `artifacts/p7-demo.webm`, VP9 1440×1000, 181.76초, 18,259,185바이트. 로그인·비밀번호는 녹화하지 않았으며 Git/Docker에서 제외한다.
- 별도 operations 이미지의 앱 역할 검사 성공 및 이미 적용된 DB의 마이그레이션 재실행 0건 확인.
- Docker 전용 standalone 플래그를 적용한 최종 이미지 빌드 성공. 실제 런타임에서 health/ready/login/정적 파일 200, 미인증 사용자 API 401, DB 연결 실패 readiness 503 확인.
- `npm run verify` 전체 성공: 타입 검사·단위 100개·DB 통합 42개·프로덕션 빌드·E2E 28개, 총 고유 테스트 170개.
- standalone을 Docker 전용으로 분리한 최종 설정에서 로컬 프로덕션 빌드와 시작·로그인·회사 전환 E2E 9개를 다시 통과했다. 위 고유 테스트 수에는 중복 합산하지 않았다.

클라우드 BuildKit에서는 주입된 프록시 호스트 DNS 해석 실패가 발생했다. 빌드 명령에서만 해당 호스트 매핑과 프록시 변수, 신뢰 CA secret mount를 전달해 해결했다. TLS 검증은 유지했으며 프록시·CA·앱 비밀을 런타임 이미지에 넣지 않았다. 운영 작업 이미지는 현재 작업공간의 600 파일 모드를 비관리자 사용자가 읽지 못하는 문제를 발견해 명시적 소유권·manifest 읽기 권한으로 보완했다. Docker VFS 빌드 캐시가 디스크를 채워 로컬 빌드가 ENOSPC로 중단된 뒤, 이번 작업의 임시 캐시·이미지만 정리해 공간을 확보하고 재검증했다. 일반 로컬 빌드는 기존 next start를 유지하고 Docker 빌드에만 WMS_STANDALONE=1을 적용한다.

## 남은 공개 배포 조건

Railway 계정·프로젝트와 서비스 변수의 안전한 연결이 필요하다. 외부 DB 준비, 실제 HTTPS URL, 로그인/권한·회사 격리 확인, 제공자 백업 보관·별도 복원 확인 후 공개 조회 계정을 공유한다. 비용이나 무료 제공 범위는 신청 시 제공자 조건을 확인하며 이 작업에서 유료 자원을 생성하지 않았다.

이 단계의 로컬 검증 결과와 외부 배포 완료는 구분한다. [배포 절차](../deploy/README.md), [백업·복원 절차](백업-복원-운영절차.md), [시연 시나리오](시연-시나리오.md)를 따른다.
