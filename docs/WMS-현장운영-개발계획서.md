# WMS 현장 운영 개발계획서

기준: [기획서 v1.1](WMS-현장운영-고도화-기획서.md), 2026-10-20. 사용자가 필수 전체 구현을 지시했다. 기존 MVP 완료 기록과 신규 고도화 완료 여부는 구분한다.

## 완료 조건

28개 필수 요구사항 전체의 화면·API·DB 구현과 AC-01~23, T01~T12 검증을 추적한다. 일부 기능·컴파일·테스트 통과만으로 전체 완료를 선언하지 않는다. 실제 수행하지 않은 8시간 부하·외부 제공자 복원·실기기·5영업일 현장 운영은 각각 미실행으로 기록한다. G4/G5에는 실제 현장과 담당자의 확인이 필요하며 합성 데이터로 대체하지 않는다.

## 구현 구조

- 기존 Next.js/Better Auth/PostgreSQL을 유지한다. 신규 마이그레이션만 추가하고 기존 전표·원장을 보존한다.
- 창고별 업무 상태를 트랜잭션 안에서 잠그고 정규 재고·불변 원장·멱등 응답을 함께 반영한다. 입고·주문·피킹·포장·실사 등의 상태 전이는 별도 엔진에서 검증한다.
- 모든 신규 데이터에 테넌트 격리를 적용한다. 계정 상태·창고 권한을 요청마다 확인하며 연계·작업·승인 계정을 구분한다.
- 외부 사건은 DB에 내구성 있게 접수하고 업무 처리와 결과 기록을 같은 트랜잭션에 묶는다. 별도 시뮬레이터 앱은 자체 UI·프로세스·SQLite 실행 저장소와 버전 있는 API 계약을 사용한다.
- 업무 화면은 검색 선택·단계별 확인·연속 이동·잔량/인계·스캔·결과 미확인 복구를 제공한다. 사용자가 UUID나 JSON을 입력하는 개발 도구 화면으로 대체하지 않는다.

## 분담과 통합 순서

모든 서브에이전트는 `gpt-6.1-sol`을 사용한다. 공통 파일과 마이그레이션 번호를 구분하여 작업하며 최종 통합·빌드·배포 판단은 주 에이전트가 맡는다.

| 담당 | 범위 | 주 소유 경로 |
| --- | --- | --- |
| workflow | 입고·출고·예약·실사·반품·교대·재고/원장 | server/v2/workflow, migration 0010 |
| identity | 초대·계정·역할·창고 권한·연계 키 | server/v2/access, identity, migration 0011 |
| masters | 거래처·위치·바코드·환산·CSV | server/v2/masters, migration 0012 |
| simulator | 외부 사건·독립 시험 앱·재현·대사 | server/v2/integration, apps/simulator, migration 0013 |
| ui | 현장 업무·기준정보·계정·연계 화면 | app/dashboard/v2, app/invitation |
| acceptance | 실제 DB 및 브라우저 독립 수락 검증 | tests/integration/v2-acceptance, tests/e2e/v2-acceptance |
| 통합 담당 | 구제품 전환·권한 우회 방지·운영·복구·전체 회귀 | migration 0014, 운영 도구·추적표 |

1. 공통 업무·마스터·인증 계약과 데이터 모델 고정.
2. 재고 보존/권한/멱등을 갖춘 실제 영속 도메인 구현.
3. 현장 화면과 외부 사건/시뮬레이터 연결.
4. 기존 자료 전환·그 전후 쓰기 경계·복구 및 운영 도구 연결.
5. 로컬 수락·회귀·독립 모의 운영으로 결함 수정 후 전체 기획 대조.

개발 도중 발견한 계약 누락은 구현·계약·수락 기준을 함께 맞춘다. 필요한 의사결정 기본안은 기획서 18장을 적용하며, 미선정 호스팅/실제 현장은 구현 완료와 구분해 기록한다.

## 검증과 전환

- GitHub Actions는 생성하거나 실행하지 않는다. 로컬 `npm run verify` 및 별도 운영 시험을 사용한다.
- DB 검증은 `_test` 전용 DB의 실행별 스키마와 NOBYPASSRLS 앱 역할을 사용한다. 실제 운영 자격을 시험에 사용하지 않는다.
- Next 개발 서버를 종료한 뒤 빌드·전체 검증을 실행한다. 기능 소유자는 독립 표적 테스트를 수행할 수 있다.
- 기존 창고는 원장/현재고 대사와 품질·위치 매핑 확인 후 전환한다. 전환 후 기존 입고/출고/이동 확정 및 역분개를 서버/DB에서 차단한다.
- 단순 DB 복원만으로 실물 거래가 되돌아간다고 판단하지 않는다. 전환 전 백업, 복원 후 원장·예약·작업·사건·권한 대사와 재개 판단을 남긴다.

상태와 근거는 [구현 추적표](WMS-현장운영-구현추적표.md)에 기록한다.
