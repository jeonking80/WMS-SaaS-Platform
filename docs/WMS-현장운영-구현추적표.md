# WMS 현장 운영 구현 추적표

기준: [기획서 v1.1](WMS-현장운영-고도화-기획서.md) · 2026-10-20. **현재 전체 상태: 추가 필수 규칙 보강의 로컬 검증 근거 확보, 모의 운영 성능 개선 진행 중. G3~G5는 통과하지 않았으며 기획 전체 완료를 선언하지 않는다.**

아래 상태는 해당 경로에 대해 확보한 검증 범위를 뜻한다. 로컬 검사나 지정 HTTP 시나리오 통과를 요구사항 전체·현장 운영 합격으로 확대하지 않는다. 세부 규칙 대조와 한계는 [독립 요구사항 감사](v2-독립-요구사항-gap-감사.md), [필수 구현 최종 대조](v2-필수구현-최종대조.md), [개발계획](WMS-현장운영-개발계획서.md)을 함께 확인한다.

[새 시험 근거](v2-performance-pages-latest.json). 이후 저장 구조 변경의 성능 판정은 별도다. 이전 빌드 `_ceZRl8gR2Kae5HHrI6GQ`의 회사 A p95 3,730ms 실패를 [원문](v2-performance-latest.json)에 보존한다.

- 세 번째 혼잡 실행 `c2267197-a92a-4374-bae0-fc0b3b920199`도 **25분 회복·성능 기준 실패**다. 정상 접수 p95 1,986/1,993ms, 정상 기술 오류율 약 0.252%, 35분에도 미완료 1,068/1,061작업이 남았다. 확인 가능한 실물 재고·원장·확정 명령 대사는 차이 0이다. 단, 회사 A는 원래 보고서 경계 7,861의 원본 snapshot이 없어 이후 7,874 경계의 사후 비교이며 회사 B는 원래 7,883 경계와 일치한다. [실패·복구 근거](v2-congestion-schema20-final-recovery.json). 전체 JSONB 집계 읽기 후보는 비교에서 약 55% 느려져 제외하고 기존 행 단위 읽기를 유지한다. [비교 근거](v2-state-reader-comparison.md). 사건 트랜잭션 사이의 시간 예산을 적용하고 [동일 600건 비교](v2-process-budget-comparison.md)에서 완료 시간 약106초 유지·타임아웃12→0을 확인했다. 전체 회귀도 통과했으나 공식 혼잡 기준 합격을 뜻하지 않는다.

- 이전 T01~T12·장애/복원·지정 HTTP 시험은 해당 보고서의 **당시 빌드와 로컬 범위** 근거를 유지한다. 새 빌드의 모의 운영·실제 제공자·현장 검증으로 옮기지 않는다.
- **8시간 실제 교대 운영은 미시작**이며, G3~G5를 통과로 표시하지 않는다.
