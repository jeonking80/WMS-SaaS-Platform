2026-10-20 18:26:39–18:29:23 (Asia/Seoul). [공개 앱](https://wms-saa-s-platform.vercel.app)에서 대표 업무 검증을 실제 실행하여 종료 코드 0, `completed: true`, `restored: true`를 확인했다. [검증 JSON](public-deployment-verification-latest.json)을 제공한다. 공개 검증 작업의 실제 명령 출력과 문서·스크립트 변경 기록을 이 저장소로 복원했다. 이 커밋에서는 공개 검사를 재실행하지 않았다. 원래 작업의 화면 이미지 파일은 이번 커밋에 포함하지 않았다.

## 기준과 배포 확인

작업공간 HEAD와 원격 main은 모두 `e16b00582a4caf213937d3e61aa27755e2f8b8e4`였다. 해당 커밋의 GitHub 커밋 상태에서 Vercel `success`와 [배포 기록](https://vercel.com/jws12/wms-saa-s-platform/8X7GVd1MRUvzEahfy5ncpw7KJYNK)을 읽었다. GitHub Actions는 만들거나 실행하지 않았다. 앱 응답은 커밋 SHA를 직접 노출하지 않으므로 HTTP 응답만으로 배포 SHA를 증명한 것은 아니다.

먼저 `scripts/verify-public-deployment.mjs`를 실행했다. health·DB readiness·로그인 화면은 HTTP 200, 비인증 me·stock·stock-ledger는 HTTP 401이며 API 응답의 서버 생성 UUID 요청 ID를 확인했다. 이어 기존 `demo:smoke`로 공개 합성 고객사의 조회자·작업자·관리자 로그인, 소속·역할, 이력 조회, 재고 정합성, 기준정보·감사 이력 접근 제한을 모두 통과했다.

## 공개 서버에서 실행한 업무

전용 합성 품목·창고·보관위치 2개·배송지 주소록을 API로 준비했다. 관리자는 실제 로그인 화면을 사용했고, 전표 작성·품목 검색·배송지 선택·저장·확정·재시도는 공개 브라우저 UI에서 실행했다.

원본·반대 전표·원장·감사 기록은 불변 이력으로 남긴다. 공개 DB 초기화, 시드 재적용, 직접 SQL 삭제는 실행하지 않았다. 초기 검증 두 번은 각각 UI 기본 5초 대기 제한과 로컬 Docker 시작 시 브라우저 네트워크 변경으로 중단됐다. 두 실행 모두 생성 데이터의 재고 복구와 비활성화를 완료했다. 첫 실행의 `WMS-000012`와 반대 전표도 보존된다. 최종 실행은 UI 대기 30초와 안전한 페이지 이동 재시도로 전체 흐름을 한 번에 통과했다.

## 재현

Node 24, 설치된 Chromium과 세 역할의 비공개 데모 자격증명을 사용한다. 클라우드 프록시를 이용할 때는 해당 환경 CA를 Chromium NSS 신뢰 저장소에 등록한 같은 셸에서 실행한다. TLS 검증을 끄지 않았다. 비밀번호·쿠키·세션 파일·로그인 화면 녹화는 산출물에 포함하지 않는다.

```sh
NODE_USE_ENV_PROXY=1 PUBLIC_DEPLOYMENT_URL=https://wms-saa-s-platform.vercel.app node scripts/verify-public-deployment.mjs

NODE_USE_ENV_PROXY=1 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium \
PUBLIC_DEPLOYMENT_URL=https://wms-saa-s-platform.vercel.app \
WMS_PUBLIC_WORKFLOW=synthetic-only \
DEMO_CREDENTIALS_FILE=artifacts/neon-demo-credentials.txt \
node scripts/verify-public-workflow.mjs
```

`DEMO_CREDENTIALS_FILE` 대신 `DEMO_ADMIN_PASSWORD`, `DEMO_WORKER_PASSWORD`, `DEMO_VIEWER_PASSWORD`를 안전하게 주입해도 된다. 매 실행은 새로운 합성 기준정보와 전표를 생성하고 정상적인 확정 취소·비활성화로 마무리하므로 감사 이력과 전표번호는 계속 남는다. 실패 시 `artifacts/public-workflow/result.json`의 `restorationError` 여부를 확인한다.
