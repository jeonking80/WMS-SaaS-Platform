# 로컬 설치 없이 확인하기 위한 다음 단계

추천 구성은 **Railway 프로젝트 하나에 웹 앱과 PostgreSQL 서비스를 분리**하는 것이다. 앱은 Docker로 실행하고 DB는 사설 연결을 사용한다. 기존 다른 서비스나 고객 DB를 연결하지 않는다. GitHub Actions는 사용하지 않는다.

현재 저장소에는 배포 파일과 데모·복원 검증 도구가 있지만 공개 웹 주소는 없다. 아래 계정 연결 이후 실제 배포를 진행해야 한다.

1. [Railway](https://railway.com/)에서 계정을 만든다. 가입 시 현재 요금·체험 조건·사용량 한도를 확인하고 선택한다. 이 프로젝트는 무료 호스팅을 보장하지 않는다.
2. GitHub 저장소 `jeonking80/WMS-SaaS-Platform`에 대한 접근을 Railway에 연결한다. 프로젝트·서비스는 이 WMS 전용으로 만든다.
3. 배포 방식과 프로젝트가 정해지면 프로젝트 이름/식별자처럼 비밀이 아닌 정보를 제공한다. 비밀번호·토큰·DB URL은 채팅이나 GitHub에 붙여 넣지 않고 제공자의 비밀 변수 설정에 넣는다.
4. [배포 절차](../deploy/README.md)에 따라 제한 앱 역할·마이그레이션 역할, 합성 데모 DB, HTTPS 인증 주소를 설정하고 검사한다. 자동 배포는 로컬 검사 및 마이그레이션 순서를 확인한 후 운용한다.
5. 실제 공개 URL에서 로그인·조회·변경 차단·재고 대조를 확인한 뒤 조회자 계정만 공유한다. 관리자·작업자 계정은 비공개로 유지한다.

GitHub의 코드 페이지, GitHub Pages, Codex 클라우드 환경 게시와 앱의 공개 배포는 서로 다르다. 이 앱은 서버와 PostgreSQL이 필요하므로 GitHub Pages에 파일만 올려서는 실행되지 않는다.
