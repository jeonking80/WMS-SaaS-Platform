# WMS Lite 기술 결정

작성일: 2026-10-19. 개발계획서 P0-01의 결정 기록이다. 실행 검증 결과는 [0단계 검증 결과](0단계-검증결과.md)에 별도로 기록한다.

## 1. 애플리케이션과 실행 환경

- Node.js 24.19.0, npm 11.9.0을 사용한다. `.nvmrc`와 `package.json`에 실행 범위를 기록한다.
- Next.js 16.4.2, React 19.3.1, TypeScript 7.0.2, Tailwind CSS 4.3.3으로 하나의 웹 애플리케이션을 구성한다.
- 패키지 직접 의존성은 정확한 버전으로 저장하고 전이 의존성은 `package-lock.json`에 고정한다. 재설치는 `npm ci`를 사용한다.
- App Router 화면과 Route Handlers를 사용한다. DB 연결이 필요한 경로는 Node.js 런타임으로 실행한다.
- 아직 업무 기능을 구현하지 않았으므로 첫 화면에는 초기 개발 상태를 표시한다.

## 2. DB와 마이그레이션

- PostgreSQL 17.9의 공식 `postgres:17.9-bookworm` 이미지를 사용한다. Docker Compose 실행 가능 여부와 이미지 다운로드를 현재 클라우드에서 확인했다.
- SQL은 `pg` 8.23.1로 실행하고, 마이그레이션은 `node-pg-migrate` 9.0.0의 SQL 파일 방식으로 관리한다. ORM은 추가하지 않는다.
- 개발 DB는 영속 볼륨, 통합 테스트 DB는 별도 컨테이너의 임시 볼륨을 사용한다. 테스트는 `_test`로 끝나는 DB 안에 독립 스키마를 만든다.
- 최초 마이그레이션은 회사 등록부 `tenants`만 생성한다. 인증·소속·업무 테이블과 RLS는 P1 이후에 추가한다.
- 현재 `postgres` 계정은 P0 로컬 초기화·연결 검증용이다. 업무 API를 만들기 전에 앱 역할과 마이그레이션 소유자 역할을 분리한다.
- 시각은 `timestamptz`로 저장하고 업무 일별 집계·표시는 `Asia/Seoul` 기준으로 설계한다.

## 3. 인증 라이브러리 선택

Better Auth 1.7.11을 선택하고 정확한 버전을 설치한다. 인증 경로·세션·초기 계정은 P1에서 구현한다.

선택 근거는 npm 공식 배포 패키지의 메타데이터·타입·구현을 확인한 결과다.

- Next.js 14~16, React 18~19 및 `pg` 8 계열 연동을 지원한다.
- `database: new Pool(...)`로 PostgreSQL 연결을 전달하고 `toNextJsHandler`로 App Router에 연결할 수 있다.
- 이메일·비밀번호 인증과 `disableSignUp` 옵션을 제공하여 공개 가입을 막을 수 있다.
- 인증 테이블은 `user`, `session`, `account`, `verification`을 포함한다. 비밀번호 해시는 라이브러리의 계정 생성 경로에서 처리한다.
- 관리자 플러그인의 서버 내부 사용자 생성 API를 초기 계정 생성 후보로 확인했다. P1에서는 공개 가입 차단뿐 아니라 외부 사용자 생성 요청 차단과 플러그인 권한 범위도 검증한다.

공식 웹 문서는 이 환경에서 접근이 거절되어 npm 배포물로 호환 인터페이스를 확인했다. 이어 `tests/integration/auth-library.test.ts`에서 실제 테스트 DB의 임의 스키마로 라이브러리 마이그레이션·사용자 생성·로그인·쿠키 세션·로그아웃·가입 차단을 검증했다. 스키마 생성 API는 `better-auth/db/migration`의 `getMigrations`를 사용했다. 이 검사는 라이브러리의 호환성 확인이며 **앱의 인증 경로·보호 화면·회사 권한은 아직 제공되지 않는다.** 실제 앱 통합은 P1 완료 조건이다.

P1 최소 검증은 인증 스키마 적용 → 초기 계정 생성 → 로그인·세션 확인 → 로그아웃·만료 확인 → 공개 가입 및 미인증 사용자 생성 거절이다. 회사·역할·RLS 검증은 인증 성공 여부와 별도로 수행한다. 최초 소속 조회와 회사 컨텍스트 설정이 서로를 선행 조건으로 요구하지 않도록 신뢰 경계를 설계한다.

참조: [Better Auth npm](https://www.npmjs.com/package/better-auth/v/1.7.11), [Next.js npm](https://www.npmjs.com/package/next/v/16.4.2), [node-pg-migrate npm](https://www.npmjs.com/package/node-pg-migrate/v/9.0.0).

## 4. 테스트와 CI

- Vitest의 unit/integration 프로젝트로 빠른 단위 검사와 실제 PostgreSQL 검사를 분리한다.
- Playwright는 프로덕션 빌드로 서버를 띄우고 Chromium에서 초기 화면·상태 확인 API를 검사한다.
- `/api/health`는 서버 응답 가능 여부, `/api/ready`는 실제 DB 연결과 최초 테이블 조회 가능 여부를 확인한다. 준비되지 않은 DB는 503을 반환한다.
- GitHub Actions는 잠금 설치·타입 검사·단위 검사·DB 마이그레이션·통합 검사·빌드·E2E를 실행한다. CI 실행 여부와 로컬에서 같은 명령을 실행한 결과는 구분해 기록한다.

## 5. 이번 단계에서 확정하지 않은 사항

인증 상세 스키마와 회사 소속 조회 경로, 반대 거래 모델, 멱등 응답 계약, 수량 상한·비활성화 규칙은 개발계획서의 해당 선행 단계에서 확정한다. 데모 배포 공급자와 비용은 아직 정하지 않았다. 현재 Docker 기반 독립 실행을 기준으로 앱·DB 자원 요구를 확인하며, 외부 데모 배포는 P7에서 진행한다.
