# 검색·선택형 배송지 주소록

작성일: 2026-10-20 (Asia/Seoul). 매 출고마다 거래처명과 배송지 전체를 입력해야 하는 문제를 해결한다. 서브에이전트는 gpt-6.1-sol만 사용했고 GitHub Actions는 사용하지 않았다.

## 사용 흐름

- 출고 작성에서 거래처·배송지 이름·주소를 검색한 뒤 결과를 선택한다. 거래처와 배송지 요약은 자동으로 채워지고 전표 저장·확정·이력까지 이어진다.
- 관리자는 출고 작성 중 또는 배송지 관리에서 한 번 등록한다. 무료 Daum 우편번호 검색으로 기본 주소를 선택하고 상세주소만 입력한다. 새 주소를 찾을 때만 외부 스크립트를 로드하며 실패 시 재시도한다. 별도 API 키나 유료 지도 설정은 요구하지 않는다.
- 작업자는 같은 회사의 활성 배송지를 선택할 수 있고 등록·수정은 관리자에게 요청한다. 조회자는 주소록 API에 접근할 수 없다.
- 배송지 관리에서 수정·비활성화한다. 주소록 수정 자체로 기존 전표 스냅샷을 변경하지 않는다. 전표를 새로 저장할 때는 선택한 활성 주소록에서 서버가 거래처와 주소를 결정한다.

## 데이터와 호환성

9번째 마이그레이션은 FORCE RLS 주소록과 회사 포함 전표 참조를 추가한다. 회사+거래처명+배송지 이름은 고유하며 앱 역할은 주소록 삭제·DDL을 수행하지 못한다. 주소록 수정과 전표 저장은 행 잠금으로 직렬화한다. 요청 본문의 회사·거래처·주소를 신뢰하여 다른 회사 정보를 연결하지 않는다.

기존 전표의 유효한 300자 이하 배송지를 회사·거래처·주소 기준으로 중복 없이 복사해 재사용한다. 더 긴 주소는 원본에 유지하고 자동 복사에서만 제외한다. 기존 전표·원장·잔량·계정은 변경하지 않는다. 이전 클라이언트의 텍스트 전표 입력과 과거 배송정보 null도 기존 규칙으로 처리한다.

## 로컬 검증

```sh
npm run db:setup
npm run db:check
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium NEXT_TELEMETRY_DISABLED=1 npm run verify
node scripts/verify-neon-init.mjs
node scripts/verify-neon-init.mjs --destinations-upgrade
node scripts/verify-neon-init.mjs --upgrade
```

타입 검사·프로덕션 빌드, 단위 테스트 134개와 실제 PostgreSQL 통합 테스트 49개가 통과했다. 브라우저 전체 실행은 31개 중 30개가 통과했다. 나머지 한 건은 기존 P4 테스트가 모든 status 요소를 하나로 가정하여 새 배송지 로딩 안내와 충돌한 선택자 문제였다. 저장 완료 문구로 선택자를 한정한 뒤 P4 3개를 다시 실행해 모두 통과했다. 확인한 고유 테스트는 총 214개이며 수정 후 전체 체인을 한 번 더 실행한 결과로 표현하지 않는다. 기존 수량·재고·멱등성 검증 조건은 유지했다.

새 통합 검증은 기존 주소 이관/중복 제거/회사 컨텍스트 복구, 원본 스냅샷 보존, 실제 RLS·복합 FK, 문자 그대로 검색·페이지·비활성 필터, 서버의 배송지 재조회와 잘못된 참조 거절을 확인한다. 새 브라우저 검증은 외부 SDK 응답을 결정적으로 대체하여 로드 실패→재시도→주소 선택→등록→다음 출고 재사용, 역할·회사 격리, 전표 저장 payload의 실제 주소록 ID, 확정 후 주소록 변경에도 이력 주소 유지까지 확인한다. 실제 외부 주소 검색 서비스의 가용성 자체를 검증한 것은 아니다.

Neon 설치 검증은 로컬 임시 PostgreSQL에서 관리자 권한이 없는 CREATEROLE 소유자로 수행했다. 빈 DB의 9개 마이그레이션·17개 테이블·10개 FORCE RLS, 기존 8개 DB의 주소록 추가/기존 주소 복사/원본 보존/반복 실행, 7개 DB의 연속 업그레이드가 모두 통과했다. 앱 역할의 격리와 주소록 삭제·RLS 해제·이력 DDL 권한 거절도 확인했다. 실제 사용자 Neon DB에 접속한 것은 아니다.

## 운영 반영

SQL·설정 도구는 main에 먼저 게시하고 새 앱 코드는 `feat/destination-address-book` 브랜치에 저장한다. 사용자가 기존 Neon `wms_demo` SQL Editor에서 [주소록 추가 SQL](../deploy/neon-delivery-destinations.sql) 전체를 실행한 뒤 main에 앱 코드를 반영한다. 마지막 결과 `address_book_ready=true`, `tenant_isolation_ready=true`를 확인한다. 초기화 SQL·데모 시드·비밀번호 변경은 필요하지 않다.
