# 백업·복원 운영 절차

백업에는 계정 해시·세션·업무 데이터가 포함될 수 있다. Git에 넣지 않고 접근을 제한한 저장소에 보관한다. 저장소의 `backups/`와 `artifacts/`는 Git에서 제외한다.

## 실제 복원 검증

```sh
npm run test:restore
```

이 명령은 현재 로컬 PostgreSQL 컨테이너 안에 임의 이름의 독립 소스 DB를 만들고, 빈 DB에 전체 마이그레이션을 적용한다. 합성 업무 데이터를 넣어 `pg_dump` custom 형식으로 백업하고 다른 새 DB에 `pg_restore --single-transaction --exit-on-error`로 복원한다. 데이터 지문·행 수·원장 대조와 제한된 앱 계정의 권한을 검증한 뒤 자신이 만든 DB와 파일만 정리한다.

`BOOTSTRAP_DATABASE_URL` 또는 `BACKUP_DATABASE_URL`의 로컬 postgres 연결이 필요하다. `BACKUP_CONTAINER` 기본값은 `wms-lite-db-1`이다. 연결 주소와 컨테이너의 PostgreSQL system_identifier가 같아야 한다. 이 스크립트는 기존 클러스터의 앱 역할이나 비밀번호를 변경하지 않는다.

## 최신 로컬 실측 결과

2026-10-20 실제 독립 DB 복원 검증은 **PASS**했다. 원본과 복원본의 17개 public 테이블 전체 행 지문과 모든 public 시퀀스 상태가 일치했고, 10개 마이그레이션·10개 강제 RLS 테이블을 확인했다. public 테이블이 추가되어 검증 목록에서 빠지면 테스트가 실패한다.

배송지 1건과 연결된 출고의 거래처·배송주소 스냅샷, 전표번호를 보존했다. 전표번호 1·2와 시퀀스 사용값 3의 간격도 보존했고, 복원 DB에서 다음 전표를 실제 생성해 번호 4가 발급되는지 확인했다. 재고 대조 불일치는 0건이며 앱 계정 인증·권한 및 회사 격리도 통과했다. 원본 지문은 그대로였으며 생성한 두 DB와 백업 파일을 정리했다. 기존 개발 DB 업무 행은 수정하지 않는다.

비밀정보를 제외한 실행 결과는 [restore-verification-latest.json](restore-verification-latest.json)에 보관한다. 이 결과는 동일 로컬 클러스터 검증이며 원격 제공자의 복원이나 실제 HTTP 로그인까지 검증한 결과는 아니다.

## 로컬 DB 백업

```sh
npm run db:backup
```

기본 연결은 `.env.local`의 `BOOTSTRAP_DATABASE_URL`이다. 기존 파일을 덮어쓰지 않으며 새 파일을 소유자 전용 모드로 만든다. 기본 출력 경로와 크기가 출력된다. `BACKUP_FILE`로 경로를 지정할 수 있다. 백업은 RLS에 의해 일부 회사가 누락되지 않도록 관리 연결로 수행하며, 앱 웹서비스에는 이 연결을 제공하지 않는다.

## 별도 DB 복원

```sh
BACKUP_FILE=/안전한/경로/백업.dump \
RESTORE_DATABASE_NAME=wms_restore_review \
npm run db:restore
```

대상 이름은 `wms_restore_`로 시작해야 하며 기존 DB와 원본 DB는 거절한다. 실패 시 원본은 건드리지 않고 새 대상 DB를 남겨 조사할 수 있게 한다. 복원 성공 메시지만으로 서비스 전환을 하지 않는다. 행 수, 인증·소속, 회사별 재고 대조와 앱 역할/RLS 검사를 먼저 수행한다.

덤프는 DB 내부 데이터·스키마·권한을 보존하지만 클러스터 역할과 비밀번호 자체는 포함하지 않는다. 이 도구는 동일한 로컬 클러스터에 역할이 존재하는 복원 검증용이다. 다른 클러스터나 외부 제공자 복원은 역할 준비, 소유권 및 앱 권한을 별도로 적용하고 다시 검증해야 한다.

## 공개 데모 운영 시

Railway 등 외부 PostgreSQL에는 이 로컬 전용 스크립트를 그대로 적용하지 않는다. 제공자의 백업 기능 또는 PostgreSQL 17 클라이언트의 암호화된 관리 연결을 사용한다. 자격 증명은 제공자 비밀 설정이나 제한된 passfile로 전달하고 명령줄·로그·Git에 넣지 않는다. TLS 검증을 끄지 않는다.

권장 운영 기준은 매일 백업, 배포·마이그레이션 전 추가 백업, 보관 기간 7일 이상이다. 이는 운영 정책 제안이며 자동 스케줄이나 원격 백업 저장소를 이번 로컬 검증으로 구축한 것은 아니다. 실제 제공자 연결 후 저장 위치·접근 권한·보관 비용·복원 주기를 확정한다.

복원 후에는 `/api/ready`, 실제 로그인, 소속/역할, 회사별 `/api/stock/reconcile`, 대표 확정 이력을 확인한다. 이전 세션 유지 여부와 인증 시크릿 변경 시 재로그인 정책을 결정한다. 장애 원인이 데이터에 있으면 앱 이미지만 이전 버전으로 바꾸어 해결된다고 가정하지 않는다. 파괴적인 다운 마이그레이션을 자동 실행하지 않는다.
