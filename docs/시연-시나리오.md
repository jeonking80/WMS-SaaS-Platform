# 약 3분 WMS 시연

실제 고객·운영 자료를 사용하지 않는다. 공개 데모는 기존 프로젝트와 분리한 앱과 `wms_demo` 등 이름에 `demo`가 포함된 전용 PostgreSQL DB를 사용한다. 빈 DB의 bootstrap → migration → 권한 부여를 먼저 완료한다. 개발용 `db:seed`, `auth:seed`의 기존 여섯 계정은 변경하지 않는다.

## 계정과 합성 데이터

공개 조회 계정은 `viewer@wms-demo.example.test`이다. 운영자가 발급한 `DEMO_VIEWER_PASSWORD`만 공개 안내할 수 있다. `worker@wms-demo.example.test`, `admin@wms-demo.example.test`는 비공개이며 각각 `DEMO_WORKER_PASSWORD`, `DEMO_ADMIN_PASSWORD`를 사용한다. 세 비밀번호는 서로 다르고 16–128자이며, 기존 로컬 테스트용 `DEMO_PASSWORD`와도 달라야 한다. 비밀번호는 호스팅 비밀 설정에 입력한다. 문서·영상·명령 인자·저장소에 기록하지 않는다. 공개 viewer는 조회만 가능하고 기준정보·전표 편집 API는 403이다.

전용 배포 비밀 파일 또는 환경 설정으로 필요한 값을 주입한 후 실행한다. 아래 명령은 비밀 값을 포함하지 않는다.

```bash
# MIGRATION_DATABASE_URL은 bootstrap/migration이 완료된 전용 데모 DB를 가리킨다.
# DEMO_DATABASE_NAME은 URL의 실제 DB 이름과 정확하게 일치해야 한다.
WMS_DEMO_SEED=synthetic-only DEMO_DATABASE_NAME=wms_demo node scripts/demo-seed.mjs
# 앱이 동일한 DB에서 실행 중이어야 한다. HTTPS 공개 주소 또는 loopback만 허용한다.
DEMO_ORIGIN=http://127.0.0.1:3000 node scripts/demo-smoke.mjs
# Playwright Chromium과 FFmpeg 설치 필요. 로그인 요청은 녹화 시작 전에 처리된다.
# 시스템 Chromium은 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH로 지정할 수 있다.
DEMO_ORIGIN=http://127.0.0.1:3000 DEMO_RECORD_VIDEO=1 DEMO_VIDEO_DIR=/tmp/wms-demo-video node scripts/demo-smoke.mjs
```

고정된 시연 테넌트에 물류센터 1곳, 로케이션 2곳, 품목 3개, 전표 6건(확정 입고 3건·출고 1건·이동 1건·출고 초안 1건)을 원자적으로 생성한다. 확정 원장 6행, 재고 4행과 감사 5행이 일치한다. 원두 재고는 입고 위치 60개·피킹 위치 25개, 머그컵 40개, 필터 8개이며 필터 부족 알림과 미확정 출고를 설명할 수 있다. 기존 테넌트가 있으면 소유권·개수·원장 대조 후 종료하고 비밀번호를 재설정하지 않는다. 데모 활동으로 개수가 달라졌으면 덮어쓰지 않고 실패한다. 재설정은 전용 DB를 백업한 후 운영 절차로 별도 수행한다.

## 촬영 순서

| 시간 | 화면 | 설명 |
|---|---|---|
| 0:00–0:35 | 대시보드 | 합성 고객사, 재고 품목, 부족 품목, 미확정 출고와 최근 확정 현황 |
| 0:35–1:20 | 현재 재고 | 입고 후 출고·로케이션 이동을 거친 수량, 재고 변동 원장 |
| 1:20–2:00 | 확정 이력 | 입고·출고·이동 전표와 읽기 전용 이력 |
| 2:00–2:30 | 재고 검색 | 원두 검색 후 입고·출고·이동 수량 확인 |
| 2:30–3:00 | 대시보드 | 공개 조회 권한, 별도 자동 검증의 테넌트 격리·중복·동시성·원장 대조 근거 안내 |

자동 녹화는 위 화면을 약 180초 동안 순회해 WebM을 생성한다. 영상에 표시되는 것은 합성 조회 계정과 업무 자료뿐이다. 세 역할의 로그인·tenant 검증, 공개 이력 상세 조회, 관리자 전용 감사 로그, viewer/worker 권한 거부, 관리자·작업자 조회, 앱의 원장 대조 API를 자동 검증한다. 변경 작업·동시성·타 테넌트 격리는 기존 통합/E2E 검증 결과를 함께 제시한다. 이 시연 스크립트는 서버를 시작하거나 종료하지 않으며 배포 성공을 주장하지 않는다.

## 로컬 실행 근거 (2026-10-20)

분리한 PostgreSQL 17.9 `wms_demo` 클러스터에서 7개 마이그레이션과 제한된 앱 역할 검사를 통과했다. 합성 seed의 최초 실행과 반복 실행, 게시 전표별 원장·잔액 대조, credential 계정 존재 검사를 통과했다. opt-in 누락·DB 이름 불일치·역할 간 동일 비밀번호·개발 비밀번호 재사용의 4가지 거부 조건도 확인했다. 세 역할의 앱 smoke를 모두 통과했다.

실제 촬영 산출물은 로컬 [artifacts/p7-demo.webm](../artifacts/p7-demo.webm)이다. 저장소에서는 제외하며 배포 파일에 포함하지 않는다. `ffprobe`로 VP9, 1440×1000, **181.76초**, 18,259,185바이트를 확인했다. 확정 이동 전표의 조회 상세 프레임도 확인했다. 로그인 화면·비밀번호·연결 정보는 녹화하지 않았다. 음성 해설은 없으며 화면 설명 자막을 포함한다. 이는 로컬 실행의 근거이며 공개 URL 배포·외부 접근 검증과 구분한다.
