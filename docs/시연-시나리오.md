# 현재 업무 화면 시연 (기획서 16.2)

약 3분 동안 현재 UI에서 입고·출고·재시도·이동·원장·A/B 고객사 격리를 확인한다. 영상은 인증 완료 후 시작하므로 비밀번호 입력은 녹화하지 않는다. 기준정보와 초안 전표는 API로 준비하고, 확정과 재시도는 실제 화면에서 실행한다. 데이터는 합성이며 실행 후 생성한 레코드만 정리한다.

## 재현 명령

Node 24, 설치된 Playwright Chromium, ffmpeg, 마이그레이션된 **로컬 전용** PostgreSQL이 필요하다. `.env.local`의 `DEMO_PASSWORD`, `MIGRATION_DATABASE_URL`과 기존 `admin.a@example.test` / `admin.b@example.test` 계정을 사용한다. 비밀 값은 문서·출력·영상에 넣지 않는다. 서버는 별도 터미널에서 실행한다. 현재 영상은 최종 `npm run verify`가 성공한 production build를 `npm run start`로 실행해 촬영한다. 아래 명령 전에 빌드가 필요하면 기존 서버를 중지한 상태에서 `npm run build`를 실행한다. 빌드·검증 중인 서버와 동시에 녹화하지 않는다. 개발 모드로 재현할 때도 `BETTER_AUTH_URL`을 앱 origin과 일치시킨다.

```bash
BETTER_AUTH_URL=http://127.0.0.1:3100 npm run start -- --hostname 127.0.0.1 --port 3100
```

```bash
DEMO_ORIGIN=http://127.0.0.1:3100 node --env-file-if-exists=.env.local scripts/record-current-demo.mjs
```

이 환경은 `/usr/bin/chromium`과 `/usr/bin/ffmpeg`를 사용한다. Playwright 전용 FFmpeg 다운로드가 네트워크 정책으로 차단된 경우, 설치된 시스템 FFmpeg를 다음과 같이 재사용할 수 있다. `ffmpeg-1013`은 현재 잠금파일의 Playwright 버전이 요구하는 경로이며 버전 변경 시 오류 안내 경로를 확인한다.

```bash
mkdir -p /tmp/wms-playwright/ffmpeg-1013
ln -s /usr/bin/ffmpeg /tmp/wms-playwright/ffmpeg-1013/ffmpeg-linux
PLAYWRIGHT_BROWSERS_PATH=/tmp/wms-playwright PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium DEMO_ORIGIN=http://127.0.0.1:3100 node --env-file-if-exists=.env.local scripts/record-current-demo.mjs
```

스크립트는 loopback 앱과 로컬 `wms_lite` / `wms_test` DB만 허용한다. 기본 산출물은 Git에서 제외된 `artifacts/current-demo/` 아래 MP4, 원본 WebM, 재고/원장 및 B사 격리 스크린샷, 비밀 없는 `result.json`이다. 실패하더라도 생성한 전표·원장·재고·기준정보 정리를 시도하며 실패는 종료 코드에 반영한다. 공개/운영 DB에는 실행하지 않는다.

## 화면 순서와 검증값

| 순서 | 조작 | 확인 |
| --- | --- | --- |
| 1 | A사 관리자 인증 후 대시보드 | 현재 업무 화면과 합성 시연 안내 |
| 2 | 준비된 입고 초안 수량 100 확인 후 확정 | 읽기 전용 전표, 재고 100 |
| 3 | 출고 30 확정 시 서버 처리 후 응답 유실 재현 | 다시 시도 버튼 표시 |
| 4 | 화면에서 출고 확정 다시 시도 | 동일 Idempotency-Key, 재고 70 |
| 5 | 이동 20 확정 | 출발 50 / 도착 20, 총재고 70 |
| 6 | 재고 및 변동 이력 조회 | 원장 +100, -30, -20, +20 및 대조 일치 |
| 7 | 비녹화 인증한 B사 세션으로 전환 | A사 품목 재고/원장 0건, 전표 API 404 |

직접 진행할 때도 전용 합성 품목·창고·로케이션을 만들고 같은 순서로 처리한다. 고객사 전환은 로그아웃 후 B사 로그인으로 수행한다. 출고 재시도는 단순 재확정이 아니라 응답 유실 후 같은 요청 키를 재사용하는 경우이므로 자동 스크립트가 이 조건을 정확히 재현한다.

## 공개 배포 후 읽기 전용 검사

실제 공개 HTTPS 주소가 준비되면 다음 명령으로 health/ready, 로그인 화면, 인증 없는 재고·원장 API의 401 및 API 응답의 UUID `x-request-id`를 확인한다. 배포·시드·마이그레이션이나 데이터 변경은 하지 않는다.

```bash
NODE_USE_ENV_PROXY=1 PUBLIC_DEPLOYMENT_URL=https://your-app.example node scripts/verify-public-deployment.mjs
```

이 검사는 실제 공개 주소가 있어야 실행 가능하다. 인증 후 역할별 조회·변경 제한은 비밀 변수를 안전하게 주입한 `DEMO_ORIGIN=https://your-app.example npm run demo:smoke`로 별도 확인한다. 로컬 녹화 성공은 공개 배포 검증 성공을 의미하지 않는다.

공개 조회 전용 데모는 로컬 A/B 녹화와 별도로 `scripts/demo-seed.mjs` 및 `scripts/demo-smoke.mjs`를 사용한다. 기존 고객사와 분리한 `demo` 이름의 전용 DB를 준비하고 bootstrap → migration → 권한 부여를 완료한다. `WMS_DEMO_SEED=synthetic-only`, URL의 실제 DB 이름과 일치하는 `DEMO_DATABASE_NAME`으로 시드한다. 공개 계정은 `viewer@wms-demo.example.test`이며 `DEMO_VIEWER_PASSWORD`를 사용한다. worker/admin 계정은 비공개로 유지하고 각각 `DEMO_WORKER_PASSWORD`, `DEMO_ADMIN_PASSWORD`를 주입한다. 세 비밀번호는 서로 다르고 기존 로컬 `DEMO_PASSWORD`와도 달라야 하며 16–128자이다. 기존 시드는 비밀번호를 재설정하지 않는다. 고정 조회 데모는 원두 입고위치 60 / 피킹위치 25 등 사전 준비된 데이터를 보여주므로 위의 100→70→50/20 실행 영상과 구분한다.

## 현재 실행 근거 (2026-10-20)

최종 로컬 검증을 통과한 production 서버에서 자동 시연을 실행했고 종료 코드 0을 확인했다. `result.json`의 `completed`와 `cleaned`는 모두 `true`이다. 입고 100, 출고 30의 동일 키 재시도 후 70, 이동 후 50/20, 원장 4행과 재고 대조, B사의 재고/원장 0건 및 A사 전표 404를 확인했다. 원장 화면의 작업자 표시도 검증했다. MP4는 H.264 1440×1000, 실제 길이 207.375초, 2,183,305바이트다. 비밀번호·세션 파일은 산출물에 저장하지 않는다.

초기 공개 주소 검사는 프록시 CONNECT403으로 앱 응답에 도달하지 못했다. 이후 접근 허용 환경에서 공개 readiness·인증·세 역할 검사와 실제 UI의 입고100 → 출고30 재시도 → 이동20 →50/20 →원장 →시험 재고 복구까지 종료 코드0으로 통과했다. [공개 배포 검증](공개배포-검증결과.md)과 [공개 실행 JSON](public-deployment-verification-latest.json)을 로컬 녹화 결과와 별도로 확인한다. 그 뒤 별도 공개 실행으로 [A↔B 양방향 API 격리](공개환경-회사격리-검증절차.md)도 통과했다. 공개 회사 전환 UI까지 별도 검증한 것은 아니다.
