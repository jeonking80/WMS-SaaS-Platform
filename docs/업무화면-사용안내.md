# WMS Lite 업무화면 사용 안내

현재 구현된 MVP의 화면 사용 순서다. 이번 변경의 전체 자동 검증·외부 DB 적용·공개 배포 완료를 의미하지 않는다. 기존 운영 DB가 주소록 마이그레이션 0008까지 적용된 상태라면 운영 담당자가 먼저 [전표번호 추가 SQL](../deploy/neon-workflow.sql)을 실행하고 마지막 준비 값 두 개가 true인지 확인한 뒤 새 앱을 배포한다. 초기화 SQL이나 데모 시드를 다시 실행하지 않는다.

## 1. 로그인과 업무 홈

`/login`에서 회사 계정으로 로그인한다. 상단의 회사·역할을 확인한다. 업무 데이터는 로그인한 회사 범위로만 조회된다.

| 역할 | 할 수 있는 업무 |
|---|---|
| 관리자 | 기준정보·배송지 관리, 전표 작성·저장·확정·확정 취소, 재고·이력·감사 조회 |
| 작업자 | 기준정보 조회, 등록된 배송지 선택, 전표 작성·저장·확정, 재고·확정 이력 조회 |
| 조회자 | 업무 홈·재고·확정 이력 조회. 초안 관리와 변경은 불가 |

업무 홈 `/dashboard`의 입고·출고·이동 작성 바로가기로 전표 작성을 시작한다. 준비되지 않은 기준정보는 등록 안내에서 확인한다. 관리자는 해당 관리 화면으로 이동하고 작업자는 관리자에게 등록을 요청한다. 오늘 입출고·확정 취소 숫자를 누르면 서울 기준 오늘의 원본 전표 확정 이력으로 이동한다. 입출고는 확정일, 확정 취소는 취소일 기준이며 자동 생성된 반대 전표는 제외한다. 처리할 전표와 최근 확정 전표의 전표번호를 누르면 해당 상세를 연다. 조회자에게는 초안 목록을 제공하지 않는다.

## 2. 처음 사용하는 회사의 기준정보 준비

관리자가 `/dashboard/master`에서 창고 → 보관위치 → 품목 순서로 등록한다. 보관위치는 화면에 따라 로케이션으로도 표시되며 같은 개념이다.

1. **창고** 탭에서 **창고 등록**을 누르고 코드·이름을 입력한 뒤 **저장**한다.
2. **보관위치** 탭에서 **보관위치 등록**을 누르고 소속 활성 창고·코드·이름을 저장한다. 내부 이동에는 같은 창고 안에 서로 다른 위치 두 개가 필요하다.
3. **품목** 탭에서 **품목 등록**을 누르고 코드·이름·최소 재고를 저장한다. 최소 재고는 0~1,000,000,000의 정수다.

탭별 코드·이름 검색, 활성/비활성 필터, 전체 건수와 페이지 이동을 제공한다. 보관위치는 창고로도 필터링한다. 목록의 **수정**을 누르면 대화상자에서 변경하며 보관위치의 소속 창고는 변경할 수 없다. 코드는 저장 시 영문 대문자로 변환한다. 오류가 나면 입력 내용과 안내를 확인하고 다시 저장한다. 저장 중에는 중복 저장과 대화상자 닫기를 막는다.

작업자는 목록만 조회할 수 있다. 비활성 정보도 과거 이력 확인을 위해 조회할 수 있으나 신규 전표에서는 활성 정보만 사용한다. 초안이 참조하거나 현재고가 남아 있는 기준정보는 비활성화할 수 없다. 창고에 활성 하위 위치가 있어도 비활성화할 수 없다.

출고를 준비하려면 관리자가 `/dashboard/delivery-destinations` 또는 출고 작성의 **새 배송지 등록**에서 거래처·배송지를 등록한다. **주소 검색**으로 기본 주소를 선택하고 상세주소를 입력한다. 외부 주소 검색 연결에 실패하면 재시도한다. 배송지 수정·비활성화는 이미 저장된 전표의 주소를 바꾸지 않는다.

## 3. 입고: 작성 → 저장 → 확정

업무 홈의 **입고 작성** 또는 `/dashboard/documents`의 **입고 작성**을 누른다. 창고와 도착 보관위치를 선택하고 품목 코드·이름으로 검색하여 품목을 추가한다. 검색 결과는 페이지를 이동하며 선택할 수 있다. 수량은 개 단위 정수이고 품목당 1~1,000,000,000, 전표당 서로 다른 품목 최대 20개다.

**전표 저장**을 누르면 초안으로 저장되고 `WMS-000001` 형태의 전표번호가 부여된다. 저장만으로 재고가 늘지 않는다. 저장된 품목·위치·수량을 확인한 뒤 확정 확인창에서 확정하면 현재고와 원장에 함께 반영된다. 저장 후 내용을 바꿨다면 다시 저장한 뒤 확정한다.

전표번호는 바뀌지 않으며 DB 전체에서 생성한다. 회사별 연속성이나 결번 없는 번호를 보장하지 않는다. 화면 링크는 해당 전표의 UUID로 연결된다.

## 4. 현재고와 변동 원인 확인

`/dashboard/stock`에서 품목 검색 선택, 창고·보관위치 필터와 페이지 이동으로 현재고를 찾는다. 품목 검색은 조회자도 사용할 수 있으며 비활성 품목의 과거 재고도 확인할 수 있다.

현재고 행의 **이력 보기**로 해당 품목·보관위치의 변동을 좁혀 본다. 원장에는 전표번호·처리 시각·증감 수량·입고/출고/이동/확정 취소·작업자를 표시한다. 전표번호를 누르면 읽기 전용 확정 이력 상세로 이동한다. 관리자·작업자는 현재고 행의 **출고 작성**으로 창고·보관위치·품목을 이어서 선택할 수 있다. 현재고·원장 대조는 불일치를 보여주며 수량을 자동 보정하지 않는다.

## 5. 출고와 내부 이동

**출고 작성**에서 창고·출발 보관위치·품목·수량을 입력하고 등록된 거래처·배송지를 검색하여 선택한다. 주소는 선택한 배송지에서 채워진다. 관리자는 필요한 배송지를 새로 등록할 수 있고 작업자는 등록된 항목을 선택한다. 저장 후 확인창에서 출발 위치·배송정보·수량을 확인하고 확정한다.

**이동 작성**에서는 같은 창고의 서로 다른 출발·도착 보관위치를 지정한다. 저장·확정하면 출발 수량이 줄고 도착 수량이 함께 늘어난다. 다른 창고 간 이동은 지원하지 않는다.

출고·이동의 참고 재고는 예약 수량이 아니다. 확정 시 서버가 현재 잔량을 다시 확인하며 하나라도 부족하면 전표 전체를 반영하지 않는다. 조회 실패나 조회 중인 수량을 0으로 해석하지 않는다. 부족하면 수량·위치를 수정하고 저장한 뒤 다시 확정한다.

## 6. 초안 취소와 확정 취소

초안은 수정·저장하거나 초안 취소할 수 있다. 초안 취소는 재고를 바꾸지 않으며 취소한 전표를 다시 확정하지 않는다.

관리자는 확정된 원본 전표에서 전체 **확정 취소**를 요청할 수 있다. 확인창에서 재고에 미칠 영향을 확인한다. 기존 원장을 지우지 않고 반대 전표·반대 원장을 생성하며 원본과 연결한다. 입고나 이동을 되돌리는 데 필요한 잔량이 없으면 거절한다. 부분 취소와 반대 전표의 재취소는 제공하지 않는다. 상세의 원본/반대 전표 연결로 관련 기록을 확인한다.

## 7. 이력·오류 처리

`/dashboard/history`는 모든 역할의 읽기 전용 확정·확정 취소 이력이다. 전표번호·품목·거래처·배송주소 등을 검색하고 날짜·유형·상태로 필터링한다. 날짜는 서울 기준이며 종료일 전체를 포함한다. **자동 생성된 취소 전표 제외**를 체크하면 반대 전표를 숨기고 원본만 조회한다. 확정 취소된 원본은 계속 표시되며 체크를 해제하면 반대 전표도 함께 볼 수 있다. `/dashboard/audit`는 관리자만 업무 처리자·동작·시각을 조회한다.

통신 실패로 확정 결과를 받지 못했다면 같은 요청 재시도 또는 상태 새로고침을 사용한다. 화면이 보존한 키·버전으로 재시도하므로 중복 반영을 방지한다. 별도 전표를 만들어 같은 수량을 다시 확정하기 전에 현재 상태를 확인한다. 버전 충돌 안내가 나오면 최신 전표를 다시 불러온다. 목록 조회가 실패하면 오류와 새로고침을 사용하고 빈 목록이나 0 재고로 판단하지 않는다.
