## 구현 결과

- 대시보드: 업무 시작 버튼, 미처리 초안, 준비할 기준정보, 서울 기준 오늘 집계에서 해당 원본 전표 이력으로 이동.
- 기준정보: 품목·창고·보관위치 탭, 이름·코드 검색, 활성 상태·페이지 처리, 등록·수정 대화상자.
- 전표: 이름·코드로 품목 검색, 작성·저장·확정 단계, 변경 불가 `WMS-000001` 번호, 한국어 상태, 저장하지 않은 변경 확인.
- 출고: 등록된 거래처·배송지 선택과 주소 검색, 현재고에서 출고 작성으로 이어지는 품목·위치 선택.
- 재고·이력: 품목·보관위치별 원장 연결, 처리자·전표번호 표시, 원본·반대 전표 연결, 역할에 맞는 읽기 전용 화면.
- 공통 화면: 현재 메뉴·회사·역할 표시, PC·태블릿 배치, 로딩·빈 결과·오류 구분.

API 요청의 테넌트 격리·역할·버전 충돌·동시 확정·응답 유실·재고 원자성 검증은 유지했다. 화면 문구와 확인창이 바뀐 테스트는 대응하는 상태와 확인 동작을 검증하도록 수정했다.

## 로컬 검증

GitHub Actions를 사용하지 않았다. Node 24, PostgreSQL 17, 시스템 Chromium에서 합성 데이터로 검증한다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium NEXT_TELEMETRY_DISABLED=1 npm run verify
node scripts/verify-neon-init.mjs
node scripts/verify-neon-init.mjs --workflow-upgrade
node scripts/verify-neon-init.mjs --destinations-upgrade
node scripts/verify-neon-init.mjs --upgrade
```

| 검사 | 최종 결과 |
|---|---|
| 타입 검사 | 통과 |
| 단위 | 147개 통과 |
| DB 통합 | 54개 통과 |
| 프로덕션 빌드 | 통과 |
| 브라우저 | 32개 시나리오 검증 완료: 전체 실행 31개 통과 후, 초안 취소 확인창 대응을 수정한 1개를 별도 재실행하여 통과 |

전체 `npm run verify` 실행은 브라우저 초안 취소 테스트의 확인창 처리 누락으로 종료 코드 1이었다. 해당 테스트에 확인창 문구 검증과 수락을 추가한 뒤 `npm run test:e2e -- tests/e2e/p2.spec.ts -g 'P2 browser'`로 재실행하여 1개 통과·종료 코드 0을 확인했다. 이 수정은 테스트에만 적용했으며 앱 코드 변경은 없었다. 전체 체인이 한 번에 성공했다고 기록하지 않는다.

Neon SQL은 신규 생성 및 이전 스키마 세 경로 모두 통과했다. 제한된 소유자 역할, 마이그레이션 10개·테이블 17개·FORCE RLS 10개, 기존 전표 유지, 반복 적용, 제한된 앱 계정 권한을 확인했다. 전표번호는 기존 전표에 부여되고 수정·재실행으로 초기화되지 않는다. 1,000,000을 넘는 번호도 잘리지 않는다.

실제 브라우저에서 업무 홈·기준정보·출고 작성·재고 화면의 PC 1440px 및 태블릿 768px 배치를 확인했다. 최종 화면 확인 기록은 별도 로컬 산출물에 보관한다.

## 공개 배포 상태

DB 준비 커밋 `e2a9a88`은 main에 푸시했다. 앱 구현은 `feat/workflow-completion` 브랜치에 준비하며, 새 앱 공개 배포는 기존 Neon DB에 번호 필드를 추가한 뒤 진행한다. 이 문서는 운영 DB 적용이나 새 앱의 공개 배포 성공을 주장하지 않는다.

현재 작업 환경에는 Neon 관리 연결이 없다. 운영 담당자는 [전표번호 추가 SQL](../deploy/neon-workflow.sql) 전체를 기존 `wms_demo`의 SQL Editor에서 한 번 실행하고 마지막 결과 `workflow_ready`, `document_numbers_ready`가 모두 true인지 확인한다. 기존 계정·전표·재고를 지우는 초기화나 데모 데이터 재생성은 필요 없다. 이후 기능 브랜치를 main에 반영하고 공개 사이트의 로그인·전표 저장·조회 흐름을 확인한다.

사용 순서는 [업무화면 사용 안내](업무화면-사용안내.md), 요청 계약은 [API 명세](API-명세.md)를 참고한다.
