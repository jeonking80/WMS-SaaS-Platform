# 01. 물류 기초

## 1. 창고에서 일어나는 일

창고는 **물건이 들어와서(입고), 머물다가(보관), 나가는(출고)** 곳입니다. WMS(Warehouse Management System, 창고관리시스템)는 이 과정에서 "무엇이, 어디에, 몇 개, 어떤 상태로" 있는지를 정확히 기록하는 시스템입니다.

```mermaid
flowchart LR
  A[입고예정 등록] --> B[수령] --> C[검수] --> D[적치]
  D --> E[(보관)]
  E --> F[예약] --> G[피킹] --> H[포장] --> I[출하]
```

### 입고 (Inbound)

| 단계 | 하는 일 | 이 시스템에서 |
| --- | --- | --- |
| 입고예정 (ASN) | 공급처가 "언제, 무엇을, 몇 개 보낸다"고 알려 줌 | 입고 작업 → 신규 등록. 재고는 아직 변하지 않음 |
| 수령 (Receiving) | 트럭에서 내려 실제 개수를 셈 | 1 수령. 수령 대기 위치(RECEIVING)에 "검수 대기" 상태로 들어감 |
| 검수 (Inspection) | 파손·불량을 확인 | 2 검수. 정상 / 보류·파손으로 판정 |
| 적치 (Putaway) | 정상품을 보관 선반에 넣음 | 3 적치. 보관 위치(STORAGE)로 이동해야 비로소 "가용" 재고가 됨 |

**예정과 실제는 다릅니다.** 공급처가 100개 보낸다고 했어도 98개가 오면 실물 기준은 98개입니다(미납 2). 105개가 오면 초과분 5개는 보류 위치에 따로 두고, 다른 책임자가 인수를 승인해야 정상 재고로 쓸 수 있습니다(과납).

### 출고 (Outbound)

| 단계 | 하는 일 | 이 시스템에서 |
| --- | --- | --- |
| 주문 접수 | 고객사가 "무엇을 몇 개, 어디로" 요청 | 출고 작업 → 신규 등록 |
| 예약·할당 (Allocation) | 그 주문에 쓸 재고를 미리 잡아 둠. 다른 주문이 가져가지 못하게 함 | 1 예약. 부족하면 전체 실패가 기본이고, "가능 수량만 예약"을 명시적으로 고를 수 있음 |
| 피킹 (Picking) | 선반에서 꺼내 작업대로 옮김 | 2 피킹. 보관 위치 → 포장 대기 위치(STAGING) |
| 포장 (Packing) | 상자에 담고 내용물을 확인 | 3 포장. 포장 하나에 최대 20명세 |
| 출하 (Shipping) | 운송사에 넘김 | 4 인계·출하. **이 순간에만** 재고가 차감됨 |

## 2. 재고 상태 — 이 프로젝트의 핵심 개념

"재고 100개"라고 해도 모두 바로 팔 수 있는 것은 아닙니다. 이 시스템은 재고를 상태별 **버킷**으로 나눕니다.

| 기호 | 이름 | 뜻 |
| --- | --- | --- |
| S | 정상 보관 | 보관 위치에 있는 정상품 |
| R | 예약 | S 중 특정 주문에 잡혀 있는 수량 (S 안에 포함) |
| A | 가용 | 새 주문에 쓸 수 있는 수량 = S − R (보관 위치이고, 실사 잠금·예약 차단이 없을 때) |
| P | 피킹·출하 대기 | 꺼내서 포장·출하를 기다리는 수량 |
| Q | 검수·적치 대기 | 수령했지만 아직 검수·적치 전 |
| B | 보류 | 파손·불량·미승인 과납 |
| H | 총 실물 | 창고 안에 실제로 있는 전부 = S + P + Q + B |

**예제** — 예정 100개에 105개가 도착:

| 시점 | Q | B | S | H | A |
| --- | --- | --- | --- | --- | --- |
| 수령 직후 | 100 | 5 | 0 | 105 | 0 |
| 100개 정상 검수·적치 | 0 | 5 | 100 | 105 | 100 |
| 주문 30개 예약 (R=30) | 0 | 5 | 100 | 105 | 70 |
| 30개 피킹 | 0 | 5 | 70 | 105 | 70 |
| 30개 출하 | 0 | 5 | 70 | 75 | 70 |

포인트: **피킹은 재고를 줄이지 않고 위치와 상태만 바꿉니다.** 창고 밖으로 나가는 출하 때만 H가 줄어듭니다.

## 3. 자주 나오는 용어

| 용어 | 뜻 |
| --- | --- |
| SKU | 재고 관리 단위. 같은 상품이라도 색·크기가 다르면 다른 SKU |
| 로케이션 (Location) | 창고 안의 주소. 예: A-01 (A구역 1번 선반) |
| EA / BOX | 낱개 / 박스 단위. 이 시스템은 EA를 기준으로 저장하고 BOX 바코드는 정수 배수로 환산 (예: BOX12 = 12 EA) |
| 실사 (Cycle Count) | 장부와 실물을 직접 세어 맞추는 작업. 차이가 있으면 다른 사람이 승인해 조정 |
| LOT / 유통기한 | 생산 묶음 번호와 기한. 식품·의약품에 필수. **이 버전에서는 범위 밖** |
| FIFO / FEFO | 먼저 들어온 것 먼저 / 유통기한 빠른 것 먼저 출고 |
| 웨이브 피킹 | 여러 주문을 묶어 한 번에 피킹하는 방식. **이 버전에서는 주문 단위 피킹** |
| 크로스도킹 | 보관 없이 입고 즉시 출고로 넘기는 방식 |
| 3PL | 여러 화주(물건 주인)의 물류를 대신 운영하는 업체 |
| 풀필먼트 | 주문 접수부터 보관·포장·배송까지 일괄 대행 |
| OTIF | On Time In Full. 납기 안에, 주문 수량 그대로 보냈는가 |
| 재고 정확도 | 장부 수량과 실물이 일치하는 비율 |

## 4. 물류 시스템의 종류

| 시스템 | 관리 대상 | 예 |
| --- | --- | --- |
| ERP | 회사 전체: 회계, 구매, 판매 | 발주서, 매출 |
| OMS | 주문 관리 | 쇼핑몰 주문 수집 |
| **WMS** | **창고 안**: 입고·보관·출고·재고 | 이 프로젝트 |
| TMS | 운송: 배차, 경로, 차량 추적 | 어느 트럭이 어디로 |
| WCS / WES | 자동화 설비 제어: 컨베이어, 소터, 로봇 | 설비에 작업 지시 |
| MES | 공장 생산: 공정 실적, 품질 | 제조 현장 |

## 5. 지원하는 회사(쿨스)와 연결해서 이해하기

공개 자료 기준으로 쿨스는 부산 신항에서 **CY/CFS**를 운영하는 항만 물류 회사이고, ICT 사업부가 WMS·TMS·항만 솔루션·MES를 만듭니다.

| 용어 | 뜻 | 이 프로젝트와의 연결 |
| --- | --- | --- |
| CY (Container Yard) | 컨테이너를 통째로 쌓아 두는 야적장 | 위치·상태 관리 개념이 같음 (컨테이너 = 관리 단위) |
| CFS (Container Freight Station) | 컨테이너를 열어 화물을 나누거나 합치는 작업장 | 입고 수령·검수·적치와 출고 피킹·포장과 같은 흐름 |
| 셔틀 운송 | 항만 내·근거리 컨테이너 운송 | TMS 영역. 이 프로젝트의 "인계 후 배송 상태" 다음 단계 |
| 디지털 트윈 | 현장을 화면에 그대로 옮긴 가상 모델 | 운영 관제의 **창고 배치도**가 가벼운 버전 |

면접에서는 "제 프로젝트의 수령→검수→적치 흐름은 CFS 반입 작업과 같은 구조이고, 운영 관제는 현장 상황을 한 화면에 모은다는 점에서 관제·디지털 트윈과 같은 목적을 가집니다" 정도로 연결하면 됩니다. 실제 항만 업무를 아는 것처럼 과장하지는 마세요.
