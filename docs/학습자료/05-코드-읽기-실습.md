# 05. 코드 읽기와 실습

## 1. 로컬 실행

```sh
npm ci
npm run env:init
docker compose --env-file .env.local --profile test up -d --wait
npm run db:setup
npm run dev
```

- `http://localhost:3000/login`에서 `admin.a@example.test`로 로그인합니다. 비밀번호는 `.env.local`의 `DEMO_PASSWORD`입니다.
- 기준정보·CSV 탭에서 창고·위치(수령·보관·포장 대기)·품목·거래처·배송지를 만든 뒤, 입고 1건과 출고 1건을 끝까지 처리해 보세요.
- AI 자유 질문을 쓰려면 `.env.local`에 `ANTHROPIC_API_KEY=...`를 넣고 개발 서버를 다시 시작합니다.

## 2. 읽는 순서 (하루 1~2개)

| 순서 | 파일 | 볼 것 |
| --- | --- | --- |
| 1 | `src/server/v2/workflow/types.ts` | Receipt·Order·Stock·Ledger 모양. 버킷 S·R·P·Q·B |
| 2 | `src/server/v2/insights/guide.ts` | 업무 하나의 "다음 할 일" 계산. 짧고 읽기 쉬움 |
| 3 | `src/server/v2/insights/analytics.ts` | 관제 지표·품절 예측. 순수 함수 연습에 좋음 |
| 4 | `src/server/v2/workflow/engine.ts` | `receipt.receive`, `order.reserve`, `order.pick`, `shipment.create`를 검색해서 버킷이 어떻게 바뀌는지 |
| 5 | `src/server/v2/workflow/index.ts` | `executeWorkflowInTransaction`: 잠금 → 대사 → 멱등 확인 → 엔진 → 저장 |
| 6 | `src/server/db/tenant.ts` + `db/migrations/1792368000010_v2-workflow.sql` | RLS 설정과 불변 트리거 |
| 7 | `src/app/dashboard/v2/ui.tsx` | `run` → `transmit` → `recover`: 화면 쪽 멱등·복구 |
| 8 | `src/app/dashboard/v2/workflow-ui.tsx` | `ActionEditor`: 스캔 → 수량 누적 → 확정 전 할 일 |
| 9 | `src/server/v2/assistant/` | AI 도구 정의와 도구 호출 루프 |
| 10 | `tests/unit/v2-insights.test.ts`, `tests/e2e/v2-ui.spec.ts` | 테스트가 무엇을 보장하는지 |

읽을 때 팁:
- 코드는 Prettier로 정렬되어 있습니다. 포맷 변경 커밋은 `git blame --ignore-revs-file .git-blame-ignore-revs`로 건너뛸 수 있습니다.
- 처음 보는 오류 코드(예: `VERSION_CONFLICT`)는 `src/app/dashboard/v2/common.tsx`의 한국어 안내문과 같이 보면 의미가 빨리 잡힙니다.

## 3. 실습 과제

쉬운 것부터 순서대로입니다. 각 과제는 별도 브랜치에서 하고, 끝나면 `npm run typecheck`와 관련 테스트를 돌려 보세요.

1. **품절 예측 기준 바꾸기**: `analytics.ts`에서 조달 기간을 3일 → 5일로 바꾸고, `tests/unit/v2-insights.test.ts`의 기대값을 손으로 다시 계산해 고치기.
2. **KPI 추가**: 관제 KPI에 "검수 대기 수량(EA)"을 추가하기. 힌트: `operationsOverview`에 필드를 추가하고 `control-ui.tsx`의 `tiles`에 한 줄.
3. **경고 추가**: 실사 잠금이 24시간 넘게 걸린 위치를 경고로 띄우기. 힌트: `state.counts`의 상태와 시각.
4. **AI 도구 추가**: "특정 주문의 진행 상황" 도구(`get_order_status`)를 추가하기. `tools.ts`에 정의와 실행을 넣고 `v2-assistant.test.ts`에 테스트 추가.
5. **SQL 연습**: 원장에서 "지난 7일 품목별 출하량 TOP 5"를 구하는 SQL을 직접 써 보고 `psql`로 실행하기.
6. **엔진 읽기**: `order.pick`이 S·R·P를 어떻게 바꾸는지 종이에 적고, `tests/unit/v2-workflow.test.ts`에서 그걸 확인하는 테스트를 찾기.
7. **멱등 실험**: 같은 `request_id`로 같은 명령을 두 번 보내고(`replayed: true` 확인), 내용을 바꿔 보내서 `IDEMPOTENCY_CONFLICT`를 확인하기.

## 4. 검증 명령

| 명령 | 내용 | 시간 |
| --- | --- | --- |
| `npm run typecheck` | 타입 검사 | 수십 초 |
| `npm run test:unit` | 단위 테스트(DB 없음) | 수 초 |
| `npm run test:integration` | 실제 PostgreSQL 통합 테스트 | 수 분 |
| `npm run build && npm run test:e2e` | 프로덕션 빌드 후 브라우저 테스트 | 10분 안팎 |
| `npm run verify` | 위 전체를 순서대로 | 15~20분 |
| `npm run format` | v2 코드 자동 정렬 | 수 초 |

GitHub Actions는 쓰지 않습니다. 개발 서버를 끈 뒤 로컬에서 `npm run verify`를 돌립니다.
